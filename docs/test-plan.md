# In-sim test plan

Checks that need a running sim. Unit tests (`dotnet test plugin/TurnTelemetry.slnx`) cover the logic. These cover what only SimHub and the sims can confirm. Record results and any surprises in the Notes column.

## Phase 1: plugin core

**Setup:**

1. Close SimHub, then build and deploy: `dotnet build plugin/TurnTelemetry/TurnTelemetry.csproj -c Release -p:Deploy=true`.
2. Start SimHub and accept the prompt to enable **Turn Telemetry**.
3. Open the plugin's tab in the left menu. Its **Live diagnostics** section is used throughout.

### Findings

- **2026-10-02, ACC (Monza, stationary):** loads, `adapter=acc`, compound `dry_compound` → `acc-dry`, pressures read correctly in psi. Wear 0.0%: ACC exposes no tyre wear, so `Caps.TyreWear = false`. All temperatures read 32.0.
- **2026-10-02, Forza Horizon 6:** SimHub game name `FH6`, generic adapter. `pos` stays 0 (open world, no lap position), and the track key is a per-event timestamp (`DT__261002114046`), so turn files can't apply. The recorder now refuses when no lap position has been seen (`Caps.LapPosition`). No steering yet (needs a Forza adapter and its raw property name). No pressure.
- **32.0 everywhere in both sims = 0 °C shown in °F.** SimHub is set to Fahrenheit. Temperature handling now honours `TemperatureUnit`, and the earlier "ACC has one zone" conclusion was withdrawn: zones are detected while driving (`Tyre.ZonesDetected`). **To check:** drive a few laps in ACC and confirm temps rise, differ per tyre, show `unit=psi/°F`, and whether `zones=` turns True.
- **2026-10-03, ACC (Silverstone, 3-4 laps, still the first build):** tyre temps stayed at 32.0 °F (= 0) while driving, so SimHub's normalised tyre temperatures are empty for ACC and the adapter needs a raw source (property name pending). Every lap ended invalid with no best; the reason wasn't shown in that build, so a "Last lap" diagnostics line was added.
- **FH6 steering:** raw property `GameRawData.Steer` (user-confirmed). `ForzaHorizonAdapter` added (Steer / 127, no TC/ABS/wear).
- **2026-10-03, ACC property browser:** all `GameData.TyreTemperature*` are 0 in ACC (confirmed). Added a raw fallback in the Kunos adapter reading SimHub's ACC `Physics` arrays. **To check:** diagnostics show `temps=raw` with plausible values, and the raw property names (rawdata toggle on) match `Physics.TyreCoreTemperature` / `Physics.TyreTempI` as one array or numbered entries.
- **2026-10-03, ACC lap logic confirmed:** lap 1 invalid (out-lap), lap 3 valid at 98.0% coverage, best 2:17.542, reference=Best.
- **2026-10-03, ACC raw names:** SimHub lists `GameRawData.Physics.TyreCoreTemperature01`..`04` (FL, FR, RL, RR; °C, ~79-86 after a few laps). The fallback still showed `temps=simhub` in the 00:06 build even though it tries this form, so a probe line (`Raw probe`) and a raw property list (`Raw tyres`) were added to the diagnostics to show why.
- **2026-10-03, ACC root cause:** the probe showed SimHub *does* fill the per-tyre average (`TyreTemperatureFrontLeft` = 85.8 °C, matching `TyreCoreTemperature01`); only Inner/Middle/Outer are empty, and raw `TyreTempI/M/O` are 0 too. So ACC reports **one temperature per tyre**, now confirmed from real data. Fix: copy the average into empty zones (any sim); the raw fallback remains for sims with no temperatures at all.
- **2026-10-03, ACC tyre temps confirmed:** 175-202 °F after the fix (`Tyre temps: SimHub gives only the tyre average on 4 tyre(s)`), `zones=False`. **ACC column complete** except #2 (property prefix), #9 (track-limits lap), #10 (reset), #13 (recorder), #17, #18.
- **2026-10-03, first tablet run of the main dashboard (ACC Silverstone):** renders correctly with live data (session, lap/delta/best, live window, tyres in °F with pressure states, TC/ABS levels, plugin info). No turns because ACC has no turn files, so turn setup was too much manual work with the recorder alone → turn editor added (D3 amended). The "—" placeholder rendered as a heavy white bar in DIN at large sizes; all dash placeholders were removed from the dashboard.
- **2026-10-03, ACC turn data:** ACC has no readable track files, and "Detect corners" needed a complete lap (the user was on the out-lap). Fixed by: SimHub track maps as a source (automatic base for every mapped track, any sim); curated official numbering for 11 tracks (2 ACC, 9 AC) verified online; circuit templates; and driving-based detection from the best available lap (≥ 30% coverage). Local survey: every map resolves (11 curated, 1 template, 15 automatic, 3 empty map files).
- **2026-10-03, AC Monza showed last turn 8 at the line, then "9" through turn 1:** a user file saved by the turn editor during the earlier AC test overrode the curated Monza data. The editor hadn't unticked the main straight because its name is Italian ("Rettifilo Partenza"), so the straight became turn 9. Fixes: multilingual straight filter; the file set aside as `monza.json.bak`; a FROM LINE button in SET T1 mode; the small panel now shows the upcoming turn (NEXT TURN / THEN) instead of the last; tyre colours are four discrete states.
- **2026-10-03, layout simplified after AC Monza test:** the NEXT label was misread as part of the number and was removed; the "then" box became SimHub's track map; Set Turn 1 (mode, tile prompt, band taps, FROM LINE) was replaced by one-tap SET LINE at the start line, with undo and reset. Contract 2.
- **2026-10-03 11:19, Windows froze (hard reset) during an AC Monza test:** Windows logged a GPU driver hang (LiveKernelEvent 141), a pre-existing issue on the test PC that isn't caused by this project. However, SimHub had opened TurnTelemetryNeon as a local WPF window on the PC monitor about 8 s before the log stops, alongside AC starting. Mitigation: Neon's blur glows (WPF BlurEffect, GPU shader) were removed (`GLOW: 0`). Recommendation: show the dashboard only on the tablet (its browser renders it, not the PC's GPU) and not as a local window.
- **2026-10-03, AC + ACC working on the tablet.** Map feedback: the map area was too small, and car dots were bigger than the track. Cause: the tablet's web client draws each car as a circle `DotRadius` *dashboard pixels* across (SimHub `Web/converters.js`), so 38/48 were huge, and the render image was set to twice the item size. Fix: turn tile halved (330 → 165 px, number 230/190 → 115/100), map panel 260 → 425 px, dots 14/18 px with 9/11 px labels, render image = item size. **To check:** the track fills the panel and the dots sit on it.

- **2026-10-03, new indicators (all three themes):** RPM under the gear (white, bright red while `CarSettings_RPMRedLineReached`); status bar TC · TC CUT · ABS · BB · MAP with a flag swatch at the far right (priority black > chequered > yellow > blue > orange > white > green); a conditions panel above a shorter tyre panel with wipers, headlights, air and track temperature. TC cut, wipers, and lights aren't normalised by SimHub: the Kunos adapter reads ACC's `Graphics.TCCut` / `WiperLV` / `LightsStage` (`TurnTelemetry.Car.*`), and other sims show N/A. **To check (ACC):** TC CUT matches the in-car value; wipers/lights change when toggled; RPM goes red on the limiter; a yellow/blue flag colours the swatch; air/track temps match the sim's HUD. **To check (AC):** TC CUT, wipers, and lights read N/A; the rest works.
- **2026-10-03, standings box + combined inputs:** steering moved into the pedals box (white trace centred on the 50 line); a standings box (from SimHub's opponent list, any sim) took the freed space. Sector times are assumed to be seconds (values over 1000 are treated as ms). **To check (ACC race and practice):** your row is highlighted and the window follows you past P6; names, best sectors, and best lap match the in-game standings; purple marks the fastest; GAP reads sensibly in a race (and in practice/qualifying, where it may be the best-lap gap or empty); lapped cars show `+n LAP(S)`. **AC:** same, offline with AI.
- **2026-10-03, sectors rated by pace:** strip titled TURNS THIS LAP. Sector boundaries are learned from SimHub's `CurrentSectorIndex` steps and saved per track; each sector is timed from the sim lap timer and rated purple (fastest by anyone), green (personal best), or yellow (slower); unreached sectors show last lap's result dimmed. Current turn and your car/row are neon blue. Microsectors were dropped. **To check (ACC and AC):** after crossing each sector line once, the S1/S2/S3 row appears with dividers where the game's sector splits happen, and `PluginsData/TurnTelemetry/sectors/...txt` is written; next session they show from the start. Sector times match the game's splits (within a few hundredths); colours match the game's own sector colours; in a session with other cars, purple only when you beat everyone.
- **2026-10-03, ACC Monza: sectors stayed white, and 4 sectors showed.** The saved file `sectors/AssettoCorsaCompetizione/monza.txt` held `0.33721 / 0.66535 / 0.66535`: saved boundaries were keyed so that all but the first looked "learned", so a live crossing at the same place was added again (a zero-width extra sector). Fixed: saved and learned boundaries are kept apart, duplicates are merged and the file re-saved, and a re-numbered index at the same place replaces the old one. White meant "no personal best to compare against": bests were only recorded from laps the plugin judged valid. Now the rating uses the game's own best sector times (from SimHub's driver list, captured as each sector starts so the new time isn't compared with itself), with the plugin's own valid-lap bests as fallback; a first time on a valid lap is green. The settings tab gains a `Sectors` line (boundaries, sim index, and the last rating with the values it used). **To check:** Monza shows S1-S3 only; after the first sector, colours are green/yellow (purple only if fastest of everyone); if anything is still white, copy the `Sectors` diagnostics lines.
- **2026-10-03, track limits per turn:** excursions are counted from the sim's tyres-out count (AC: 3+, ACC: all 4; raw property found by name) with the lap-invalidation flag as fallback, pinned to the nearest turn. **To check (ACC and AC):** the settings-tab `Limits` line shows `raw=` a found property (e.g. `Physics.NumberOfTyresOut`) and `tyres out` changing as you put wheels off; putting all four wheels off at a turn turns its number red with a bright bar, which goes dim on the next lap; `TRACK LIMITS n` counts up; kerb-hopping over one exit counts once. If `raw=not found`, it falls back to invalidations (first per lap only).
- **2026-10-03, ACC: a deliberately slow lap rated green; a second lap rated white.** Cause: own sector bests were only recorded from laps the plugin judged valid, and the earlier laps were invalidated by track-limit testing, so no best existed (and the game's bests weren't reaching the rating). Fix: a sector counts if there was no track-limit excursion or pit lane in that sector, regardless of lap validity; a sector with one is red (`INVALID`). The game's bests now also come from SimHub's `Sector1..3BestTime`. Diagnostics add `bests: S1 own=… game=… fastest=…`. **To check:** a slow lap after a clean one is yellow; going off in one sector makes only that sector red; if `game=-` everywhere, the game's sector bests aren't available in this sim and the plugin's own timing is used.
- **2026-10-03, ACC Brands Hatch wet quick race: no track limits recorded.** SimHub's ACC reader does have `Physics.NumberOfTyresOut` (checked in `ACSharedMemory.dll`; AC's is the same name), but the plugin only looked for it by searching SimHub's property-name list, which includes GameRawData only when SimHub's raw-data option is on. So tyres-out was never found, and only the lap-invalidation fallback ran: enough in the earlier Monza practice, not in this race. Fix: read `Physics.NumberOfTyresOut` by name first (works regardless of that option, as the wipers do), with the name search as fallback. **To check:** the settings-tab `Limits` line shows `raw=Physics.NumberOfTyresOut` and `tyres out` changing; going four wheels off in a race marks the turn.
- **2026-10-03, ACC race, live check via SimHub Property Server (port 18082) while going off at T5-T7, Brands Hatch:** `acc.physics.NumberOfTyresOut` stayed 0 throughout (the field exists in SimHub's ACC struct but ACC doesn't fill it), `acc.graphics.isValidLap` / `LapInvalidated` stayed valid (ACC races give track-limit warnings, not invalidation), `PenaltyTime` 0. The plugin read the property correctly (`Car.TyresOut` = 0, not null). **Conclusion:** ACC exposes no per-excursion track-limit signal in races; detection works in ACC practice/qualifying (lap invalidation: first offence per lap) and in AC (tyres out). Open: whether tyre dirt (`TyreDirt*`) is a usable off-track hint (grass/gravel only).
- **2026-10-03, decision (user): just label it.** ACC races show `TRACK LIMITS N/A IN RACE`; no heuristic (tyre dirt) was added. **To check:** the label appears in an ACC race and not in ACC practice or AC.
- **2026-10-03, first problem report (AC Monza practice):** the report worked end to end (versions, diagnostics, event log, settings, SimHub log lines). It confirmed **AC track limits work**: `track limits: tyres out at 0.163 -> T1 (tyres out 3)` with `raw=Physics.NumberOfTyresOut`. It also showed: SimHub's files are all stamped 1.0.0.0 (version now read from Windows' installed-programs entry, e.g. 9.12.9); the session started twice within 0.1 s (the log now records which session-key part changed, so the next report shows why); a noise line "sector none yet" (removed).
- **2026-10-03, AC Laguna Seca (`fn_lagunaseca`): no track limits even fully off the road at T3-T5.** With every-excursion logging, AC's `NumberOfTyresOut` never left 0 there (Monza: 3 at T1). Cause is the track's surface data, not the plugin: AC counts a tyre as out only on surfaces with `IS_VALID_TRACK=0`, and Laguna Seca's `data/surfaces.ini` (identical in `ks_laguna_seca`) sets **GRAVEL and SAND to valid track** (only PAINT, CNCGREEN, RCVTP, CUTGRV are invalid); AC's global defaults mark GRASS/SAND invalid, but the track overrides SAND. Documented as a known limit; the event log now records every off-track moment (`tyres off track: peak N at pos (near Tx) counted / below the limit`), so near misses are visible in reports.
